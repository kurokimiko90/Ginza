② 網頁載入與組場景

打開網頁後，瀏覽器在數秒內把兩份 JSON 變成可走動的街區。

人工（維護者／使用者操作） 自動腳本 LLM（本專案未使用） 檔案 / 儲存 外部 API
全部在瀏覽器內完成；任何一步失敗，畫面停在「載入失敗：原因」。

解決什麼問題

上千棟建築、上萬個店面零件、兩千多個行人，若一個一個畫會很慢。這一步把同類物件合併成少數幾批繪製，並在開始前完成地標校正。

怎麼處理

順序做什麼白話說明
1讀資料同時下載 city.json 與 roads.json
2校正依平行步道修正中央通り車道寬度；和光、GINZA SIX 套用官方高度（不改原始資料）
3建築外形擠出成樓，貼上程序化窗格；地標用專屬立面
4街景店面櫥窗與店內、招牌燈箱、花壇行道樹、路燈信號
5人車依道路網生成，靠左行駛、沿人行道行走
6夜間照明圖把路燈、招牌、櫥窗位置畫成一張光照圖，讓低處地面與牆面入夜變亮
7時間與視角依現在東京時間（或 ?hour=）設定光線；若網址帶 #@ 視角就直接進入漫遊

考慮了哪些情況

情境怎麼應對
用 file:// 直接開 index.html瀏覽器會擋 ES module 與 fetch；必須用本機伺服器
JSON 載入失敗畫面顯示「載入失敗：原因」，主控台記錄錯誤
夜晚時間開啟時間限制在 05:00–22:00 之間
為什麼這樣設計
同材質物件合併為一批、人車用實例化繪製：數量級是「幾十次繪製」而不是「上萬次」，一般筆電也能流暢走動。
