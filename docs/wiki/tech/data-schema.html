資料格式

網頁讀的兩份 JSON。座標單位為公尺，原點為銀座四丁目，x 往東、z 往南。

解決什麼問題

網頁的所有內容都從這兩份檔案長出來。改規則前先確認欄位語意，避免前後端（腳本與網頁）理解不一致。

city.json   { origin:[lat,lon], bounds:[minX,minZ,maxX,maxZ],
              landmarks:[{label, id, target:[x,z], height}],
              signs:[{text, kind, cat?, x, z, nx, nz, room, top, slot, prio}],
              boards:[{names[], x, z, nx, nz, top}],
              streetSigns:[{name, en, x, z, dx, dz}], streets:[{name, en, x, z}],
              clock:{x, z, base, face:[x,z]},
              buildings:[{id, height, base, method, tone, outers:[[[x,z],…]], holes?, name?}] }
roads.json  [{kind, width, points:[[x,z],…], name?, en?}]
欄位意思注意
signs.kindcrown（大樓頂部）／shop／restaurant／cafe…既有語意：所有 shop 標籤都歸成 "shop"
signs.catOSM shop 或 amenity 的原值，例如 jewelry、convenience2026-10-11 新增；只有店家招牌有，頂部招牌沒有
signs.nx, nz招牌所在外牆朝外的方向店內業態比對時要求方向一致
buildings.method高度來源估算值不要當實測
buildings.base架空建築的底部高度base ≥ 2 的不做店面
